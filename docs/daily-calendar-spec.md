# 日毎カレンダーページ 仕様書

## 概要

チームメンバーの1日のスケジュールを時間軸で横並びに表示し、誰が何時に何をしているかを一目で把握できるページ。

## 機能要件

### 1. 自分のスケジュール列（必須・常に一番左）
- 自分のスケジュールを表示
- タスクの追加・編集・削除が可能
- タスクには「タイトル」「開始時間」「終了時間」「説明（任意）」

### 2. メンバーのスケジュール列（追加可能）
- 「+ メンバー追加」ボタンで他メンバーの列を追加
- メンバー選択ドロップダウン（既存membersテーブルから取得）
- 追加したメンバーの列は「×」ボタンで削除可能
- メンバーのスケジュールは閲覧のみ（編集不可）

### 3. 日付ナビゲーション
- 前日・翌日への移動ボタン
- 「今日」ボタンで本日に戻る
- 日付選択（カレンダーピッカー）

### 4. 時間軸表示
- 縦軸: 時間（9:00〜23:00、30分刻み または 1時間刻み）
- 現在時刻インジケーター（赤い横線）
- スクロール可能（縦方向）

### 5. タスク表示
- タスクブロックは開始〜終了時間の高さで表示
- 色分け（カテゴリ or ユーザーごと）
- ホバーで詳細表示

## データベース設計

### 新規テーブル: `daily_schedules`

```sql
CREATE TABLE daily_schedules (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  description TEXT,
  start_time TIMESTAMPTZ NOT NULL,
  end_time TIMESTAMPTZ NOT NULL,
  color TEXT DEFAULT '#3b82f6',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- RLSポリシー
ALTER TABLE daily_schedules ENABLE ROW LEVEL SECURITY;

-- 自分のスケジュールは全操作可能
CREATE POLICY "Users can manage own schedules" ON daily_schedules
  FOR ALL USING (auth.uid() = user_id);

-- 他ユーザーのスケジュールは閲覧のみ
CREATE POLICY "Users can view all schedules" ON daily_schedules
  FOR SELECT USING (true);
```

## UI/UXの詳細

### タスク追加方法
1. **ダブルクリック**: 時間帯をダブルクリック → 追加モーダル表示
2. **ドラッグ**: 時間帯をドラッグして範囲選択 → 追加モーダル表示

### タスク編集方法
1. タスクをクリック → 編集モーダル表示
2. タスクのリサイズ（上下の端をドラッグ）で時間変更
3. タスクのドラッグ&ドロップで時間移動

### レスポンシブ対応
- モバイル: 1列表示（自分のスケジュールのみ）、メンバー切り替えタブ
- デスクトップ: 複数列表示
